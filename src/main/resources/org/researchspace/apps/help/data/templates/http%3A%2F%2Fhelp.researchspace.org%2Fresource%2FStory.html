Stories

A story is a guided tour of slides. Each slide has a title, a text and the URL of a state of a page, for example a map with a given view, year, historical maps and colours. While the reader moves from slide to slide, the page changes accordingly, without reloading.

Writing a story

  1. Open the page the story is about. Its components must be inside an <app-state> with auto-sync="true", and declare the state they share with shared-state-vars.
  2. Set up the view of the first slide (zoom, year, historical maps, colours, …) and copy the URL from the address bar.
  3. In Stories (also in the Administration page and in Thinking Frames), create a story, add a slide, write its text and paste the URL.
  4. Repeat for the other slides, save, and use Preview to try it.

A link in a slide text can point to another slide: insert a link to #3 to go to slide 3.

Showing a story

Place <rs-story> inside the same <app-state> as the components it drives:

\[[#if (urlParam "story")]] \[[/if]] ]]>

Opening the page with ?story=<story IRI> then shows the story. The current slide is kept in the URL (storySlide), so a link opens the story at that slide. When a slide shows another page, that page is opened and an <rs-story> on it continues the story.

When a slide is shown, the components mentioned by any slide of the story get the state of that slide; those that the slide does not mention go back to their defaults, so that the state of the previous slide does not leak into it.

Data model and queries

Stories are LDP resources of the container http://www.researchspace.org/resource/system/storyContainer in the default repository, modelled with CIDOC-CRM:

a crm:E73_Information_Object ; crm:P2_has_type ; rdfs:label "Title" ; crm:P1_is_identified_by ; # E41, P190 "Title" crm:P67i_is_referred_to_by ; # E73 typed text_type/description, P190 crm:P94i_was_created_by ; # E65, P14 creator, P4 E52 P82 date crm:P106_is_composed_of , . a crm:E73_Information_Object ; crm:P2_has_type ; crm:P106i_forms_part_of ; rso:PX_has_sequence_position 1 ; crm:P1_is_identified_by ; # slide title crm:P190_has_symbolic_content "

Text

"^^rdf:HTML ; crm:P67_refers_to . a crmdig:D1_Digital_Object ; crm:P2_has_type ; crm:P1_is_identified_by . # E42 typed resource_type/url, P190 "/resource/..."]]>

CIDOC-CRM has no construct for the order of parts, so the position of a slide is given by rso:PX_has_sequence_position.

Listing stories

SELECT ?story ?title WHERE { ?story crm:P2_has_type ; crm:P1_is_identified_by ?appellation . ?appellation crm:P2_has_type ; crm:P190_has_symbolic_content ?title . }]]>

Slides of a story, in order

PREFIX rso: SELECT ?slide ?position ?text ?stateUrl WHERE { crm:P106_is_composed_of ?slide . ?slide rso:PX_has_sequence_position ?position . OPTIONAL { ?slide crm:P190_has_symbolic_content ?text } OPTIONAL { ?slide crm:P67_refers_to/crm:P1_is_identified_by/crm:P190_has_symbolic_content ?stateUrl } } ORDER BY ?position]]>

In a semantic-query template, query with repository="default" and render the HTML text of a slide with triple braces: {{{{raw}}}}{{{text.value}}}{{{{/raw}}}}. The text is written by story authors; rs-story sanitizes it before showing it.
