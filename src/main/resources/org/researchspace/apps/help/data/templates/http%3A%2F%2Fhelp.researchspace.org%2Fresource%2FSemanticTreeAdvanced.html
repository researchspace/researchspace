Semantic Tree Advanced

The <semantic-tree-advanced> component extends the base <semantic-tree> with advanced capabilities for interactive tree visualizations backed by SPARQL queries.

It supports:

  • Lazy loading — load child nodes on demand via a dedicated SPARQL query
  • Search — find nodes by text and highlight matching paths in the tree
  • Sorting — sort nodes by any SPARQL binding (string, number, or date)
  • Filtering — exclude nodes based on SPARQL conditions
  • Related node discovery — hover menu to find related nodes via SPARQL queries
  • Node highlighting — programmatic highlighting via the event system
  • Tree lines — visual connector lines between parent and child nodes

Architecture

  • SemanticTreeAdvanced handles SPARQL queries, state management, caching, and data transformation.
  • TreeAdvanced renders the HTML tree with collapsible nodes, hover menus, tree lines, and Handlebars templates.
  • D3Tree is used only when provider is set to a D3 variant.

Data Flow

  1. Executes the main query to fetch node-parent pairs.
  2. Transforms SPARQL bindings into a graph (adjacency list).
  3. Breaks graph cycles, identifies roots, converts to an immutable forest.
  4. If expand-query is provided, children are loaded lazily on click.

Code-only examples

The following examples show configuration patterns. They use generic SPARQL queries that you should adapt to your ontology.

Search

Add search-query and path-to-root-query to enable full-text search with path expansion.

rico:isOrWasIncludedIn* ?ancestor . } ' search-placeholder='Search records...' collapsed=true > ]]>

Important: Both search-query and path-to-root-query should be provided together. Without path-to-root-query, deep search results will not be revealed.

Hover menu to find nodes sharing a property (sender, place, date, etc.).

rico:isOrWasIncludedIn* ?ancestor . }' related-node-criteria='[ { "label": "Same Sender", "icon": "fa fa-user", "query": "SELECT ?node WHERE { <$__nodeIri__> rico:hasSender ?s . ?node rico:hasSender ?s . FILTER(?node != <$__nodeIri__>) }", "description": "Find records from the same sender" }, { "label": "Same Place", "icon": "fa fa-map-marker", "query": "SELECT ?node WHERE { <$__nodeIri__> rico:isAssociatedWithPlace ?p . ?node rico:isAssociatedWithPlace ?p . Performance Considerations

Lazy Loading
Use expand-query for large trees. Loading thousands of nodes upfront will be slow.
Batch Expansion
Search highlighting batches multiple node expansions into a single SPARQL query using VALUES.
Caching
With enable-cache=true (default), expanded children are cached in memory. Cleared when filters change.
Memoization
Computed tree data is memoized to prevent expanded folders from collapsing on unrelated state changes.
Performance Tracking
Set enable-performance-tracking=true for query time, render time, and cache metrics.

Troubleshooting

ProblemCauseSolution

Filters don't exclude nodesCondition query doesn't project ?nodeEnsure the SELECT returns ?node.
Sorting has no effectBinding name mismatchThe binding must exactly match a SPARQL projection variable.

Nodes show raw URILabel not projected in SELECTAdd label variables to the SELECT clause, not just the WHERE.
