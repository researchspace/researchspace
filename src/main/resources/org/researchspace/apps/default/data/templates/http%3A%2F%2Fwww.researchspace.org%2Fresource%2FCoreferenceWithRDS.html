[[!-- Coreference an existing record with entries of the Swiss Art Research Reference Data Service (RDS), searched through the rds-reconciliation REST service (config/services/rds-reconciliation.ttl). Same structure as rsp:ImportFromWikidata - a search, a table of results and an action per result - but nothing is imported: the action records the reference entry as an identifier of the record. Options: viewId (required) prefix for the ids of the components recordIri (required) IRI of the record to coreference recordLabel (optional) pre-fills the search box scheme (optional) authority document of the record; when set, the coreference is saved in that graph of the "authorities" repository, otherwise in the data graph of the default one, exactly like the record forms do types (optional) preselected RDS type(s), comma-separated, e.g. "Person" or "Person,Group" datasets (optional) preselected RDS dataset(s), comma-separated, e.g. "gnd" or "gnd,ulan,wikidata" limit (optional) maximum number of results, 20 by default When types / datasets are not given nothing is preselected, i.e. the search is not restricted. All the types and datasets of the service are always listed, so the preselection can be changed or cleared by the user. A preselection that is one of the options simply selects it; a list, e.g. "Person,Group", is added as an option of its own, shown as "Person, Group". When types are requested, entries that have none of them are left out, and the type shown for a group is the requested type(s) its entries have: a search for Place shows Berlin in Wikidata, typed Concept and Place, as Place. What is saved for every coreference (see the insertPattern below), each new entity with a primary appellation in the shape of the entity/primary_appellation KP: crm:P1_is_identified_by . a crm:E42_Identifier ; # /coreference/ crm:P190_has_symbolic_content "IRI of the reference entry" ; crm:P2_has_type . a crm:E15_Identifier_Assignment ; # /assignment crm:P140_assigned_attribute_to ; crm:P37_assigned ; crm:P14_carried_out_by ; # ?__useruri__, as in the entity form records crm:P4_has_time-span ; # crm:E52_Time-Span, P82_at_some_time_within NOW() crm:P33_used_specific_technique . # crm:E29_Design_or_Procedure When the reference entry has a description in RDS, it becomes the description of the identifier, in the shape of the entity/description KP, so that it is shown and edited like any other entity description: crm:P67i_is_referred_to_by . a crm:E73_Information_Object ; # /description crm:P2_has_type ; crm:P1_is_identified_by /primary_appellation . /primary_appellation a crm:E41_Appellation ; crm:P2_has_type ; crm:P190_has_symbolic_content "description of the reference entry" . The "Add coreference" triggers pass the entries as {"iri": ..., "description": ...}; the description is written with {{stringify}}, which escapes quotes and line breaks for the JSON of the event data. Nothing is written when the record already has the identifier. "Remove" on a coreferenced entry deletes all of the above again, see the deletePattern of the remove form; so does removing the identifier in the "Other identifier" field of the record, see the deletePattern of the entity/identifier KP. --]] [[!-- Everything is inside a client-side template, like in rsp:ImportFromExternalSource: the options of the including inline-template are inherited by it. --]]
