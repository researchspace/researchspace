Sigma Graph Component

The <semantic-sigma-graph> component visualises RDF graph data using Sigma.js. Sigma renders through WebGL, making it suitable for interactive graph exploration, including larger graphs where the older semantic graph component may become less responsive.

The component is designed for graph-shaped SPARQL CONSTRUCT results. It can be configured with colours, sizing, layout controls, edge filtering, search, grouping, graph persistence and event-based integration with other ResearchSpace components. If no layout is specified, the component applies the lightweight deterministic circular layout once after mounting. Other layouts are available from the layout selector. Choose a layout and press Apply or Start; navigation controls preserve that choice.

If the graph needs to communicate with other components, or if more than one Sigma graph is used on the same page, provide a stable id. The id is used as the component-level event identity so that events from different graph instances do not interfere with each other.

Layout note: the default initial presentation is circular. Set layout="noverlap", layout="circlepack", layout="random" or another layout value only when a graph should use a different initial layout. Force and ForceAtlas2 are available in the same layout selector, but their supervisors are created lazily when started or configured as the initial layout. Further node clicks and expansions can restart the applied continuous layout.

Try all graph controls

This live example starts with ForceAtlas2. Use its layout menu to try all six layouts, search for a displayed node label, filter relationships, zoom, and return to the whole graph. Click Alice or Bob to add neighbours from the example's expansion query.

When to use it

Use this component when the user needs to explore relationships between RDF resources, rather than only inspect a tabular result set. Typical use cases include object networks, people and organisation networks, provenance chains, event networks, collection-item relationships, and any view where users need to follow links interactively.

For small, static diagrams the older Semantic Graph component may still be sufficient. Use <semantic-sigma-graph> where interaction, layout control, incremental graph expansion, filtering or WebGL performance is important.

Basic usage

The minimum useful configuration is a SPARQL CONSTRUCT query and a height. The query should construct subject-predicate-object triples. Include rdf:type triples when you want type-based colours or grouping.

The examples below are rendered as static code blocks. Copy an example into a normal page to run it. Use layout to choose the initial layout; if omitted, the graph starts with circular. The live example above explicitly starts with ForceAtlas2. 

<semantic-sigma-graph
  id="resource-network"
  height="500px"
  query="
    prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
    prefix person: <http://example.com/person/>
    prefix foaf: <http://xmlns.com/foaf/0.1/>

    CONSTRUCT {
      ?s ?p ?o .
    } WHERE {
      VALUES (?s ?p ?o) {
        (person:alice foaf:knows person:bob)
        (person:alice foaf:knows person:carol)
        (person:bob rdf:type foaf:Person)
        (person:carol rdf:type foaf:Person)
        (person:alice rdf:type foaf:Person)
      }
    }">
</semantic-sigma-graph>

Complete example: layouts, search, filters and navigation

The live example above uses the complete configuration below. Its initial and expansion queries supply their triples through VALUES, so no example dataset needs to be imported. Resource and relationship labels follow your installation's label service. Copy this component into a page to test every control together. 

<semantic-sigma-graph
  id="sigma-layout-controls-demo"
  height="600px"
  width="100%"
  layout="forceAtlas2"
  layout-run-duration="10000"
  max-force-nodes="500"
  controls="true"
  search-box="true"
  edge-filter="true"
  query="
    prefix rdfs: <http://www.w3.org/2000/01/rdf-schema#>
    prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
    prefix person: <http://example.com/person/>
    prefix org: <http://example.com/org/>
    prefix foaf: <http://xmlns.com/foaf/0.1/>

    CONSTRUCT {
      ?s ?p ?o .
    } WHERE {
      SELECT ?s ?p ?o WHERE {
        VALUES (?s ?p ?o) {
          (person:alice foaf:knows person:bob)
          (person:alice foaf:knows person:carol)
          (person:carol foaf:knows person:mike)
          (person:mike foaf:knows person:carol)
          (person:bob foaf:knows person:carol)
          (person:alice foaf:knows person:mike)
          (person:alice foaf:member org:W3C)
          (person:mike foaf:member org:W3C)
          (person:alice rdf:type foaf:Person)
          (person:carol rdf:type foaf:Person)
          (person:mike rdf:type foaf:Person)
          (person:bob rdf:type foaf:Person)
          (org:W3C rdf:type foaf:Organization)

      }
    }"

    CONSTRUCT {
      ?s ?p ?o .
      ?s rdf:type foaf:Person .

Layout choices and buttons

Open the toolbar button labelled Choose graph layout, select an algorithm, and press its action button. Changing the dropdown prepares a choice; Apply or Start activates it. Search, filters, zoom and See whole graph preserve both the dropdown selection and the applied layout.

LayoutAction buttonWhat it does
Circular (circular)ApplyPlaces nodes around a circle once.
Circle pack (circlepack)ApplyPacks nodes into circles once.
Random (random)ApplyAssigns a new random placement once.
Noverlap (noverlap)ApplyReduces overlap from the current positions.
Force (force)Start / RestartRuns a continuous layout for small graphs; switches to ForceAtlas2 above the configured node limit.
ForceAtlas2 (forceAtlas2)Start / RestartRuns the force-directed layout in a worker.

Restart begins a fresh run period for a running continuous layout. Stop stops the active continuous layout immediately, even if a different option is selected in the dropdown. Stop is disabled when no continuous layout is active.

Keep one layout and hide the layout menu

Set layout-controls="false" alongside controls="true" to retain Zoom In, Zoom Out and See whole graph while hiding the layout button and its menu, including Start/Restart/Stop. Set layout to choose the algorithm. Search and edge filtering remain independently configurable, and node expansion continues to use the configured layout.

<semantic-sigma-graph
  id="fixed-layout-network"
  height="500px"
  width="100%"
  layout="forceAtlas2"
  layout-run-duration="10000"
  controls="true"
  layout-controls="false"
  search-box="true"
  edge-filter="true"
  query="
    PREFIX person: <http://example.com/person/>
    PREFIX foaf: <http://xmlns.com/foaf/0.1/>
    CONSTRUCT { ?s foaf:knows ?o }
    WHERE {
      VALUES (?s ?o) {
        (person:alice person:bob)
        (person:alice person:carol)
        (person:bob person:carol)
      }
    }">
</semantic-sigma-graph>

layout-controls defaults to true, so existing pages retain the layout menu. controls="false" hides the entire zoom/layout toolbar regardless of layout-controls. Hiding the menu does not stop the layout: the usual run-duration limit, visibility pauses and restart on node clicks still apply.

Initial layout and ForceAtlas2

Continuous layouts stop after layout-run-duration milliseconds of active time (default 10000; use 0 for unlimited). Clicking or expanding a node restarts the applied continuous layout and gives it a fresh run period. A click reuses an already running layout. Layouts pause while their graph is outside the viewport or its document is hidden. Stop prevents pending query results, dragging and visibility changes from restarting the layout; a new deliberate node click or expansion starts exploration again.

The component applies circular as the default initial layout. This is cheap, deterministic and avoids the worker pressure associated with force-directed layouts. Layout supervisors are created only when a continuous layout starts. Static layouts run once when requested. To use a different initial layout, set the component's layout attribute, for example layout="noverlap", layout="circlepack" or layout="random".

On pages with many graph instances, omit layout unless a particular example needs a different first presentation. The omitted value means circular, and users can still open the layout control and apply another layout to the graph they are inspecting.

ForceAtlas2 is available from the same layout selector as the synchronous layouts. Its worker is created when that layout starts. Use Start to apply a continuous layout, or configure it as the initial layout. Once applied, further node clicks and expansions can restart it automatically.

Available layouts are:

  • circular: default initial layout; deterministic circular placement.
  • noverlap: reduces node overlap when applied.
  • circlepack: packed circular layout.
  • random: quick random placement.
  • force: main-thread animation for small graphs; above max-force-nodes (default 500), ForceAtlas2 is used instead.
  • forceAtlas2: worker-based force-directed layout; mounted and started only when requested.

Colour scheme and sizing

Use colours to map RDF types to node colours. The component checks the node's rdf:type values and uses the first configured type colour it finds. The optional node and edge keys define fallback colours.

Grouping repeated related nodes

Grouping is useful when one source node has many related target nodes of the same type through the same predicate. Instead of drawing every target immediately, the component draws a group node labelled with the grouped type and count.

The threshold controls when grouping starts. The behaviour controls what happens when a group is expanded:

  • expand: keep the group node and attach the children to it.
  • replace: replace the group node with its children.
  • none: show the group but do not expand it on click.

The following example is shown as code only. Documentation pages should avoid mounting many live Sigma graphs at once because each live graph creates a WebGL context. 

<semantic-sigma-graph
  id="grouping-demo"
  height="500px"
  controls="true"
  query="
    prefix rdf: <http://www.w3.org/1999/02/22-rdf-syntax-ns#>
    prefix person: <http://example.com/person/>
    prefix foaf: <http://xmlns.com/foaf/0.1/>

    CONSTRUCT {
      ?s ?p ?o .
    } WHERE {
      VALUES (?s ?p ?o) {
        (person:alice foaf:knows person:bob)
        (person:alice foaf:knows person:carol)
        (person:alice foaf:knows person:derek)
        (person:alice foaf:knows person:mike)
        (person:alice rdf:type foaf:Person)
        (person:bob rdf:type foaf:Person)
        (person:carol rdf:type foaf:Person)
        (person:derek rdf:type foaf:Person)
        (person:mike rdf:type foaf:Person)
      }
    }"
  grouping='{
    "enabled": true,
    "threshold": 2,
    "behaviour": "replace"
  }'
  colours='{
    "http://xmlns.com/foaf/0.1/Person": "#2980b9"
  }'>
</semantic-sigma-graph>

Loading more data when a node is clicked

Use node-query to expand the graph on demand. The query is executed when a non-grouped node is clicked. Use either ?subject or $subject as the placeholder; the component replaces it with the clicked node IRI before executing the query. 

<semantic-sigma-graph
  id="expandable-network"
  height="600px"
  controls="true"
  search-box="true"
  query="
    CONSTRUCT {
      ?resource ?p ?o .
    } WHERE {
      BIND(<http://example.com/person/alice> AS ?resource)
      ?resource ?p ?o .
    }"
  node-query="
    CONSTRUCT {
      ?subject ?p ?o .
      ?o ?op ?oo .
    } WHERE {
      ?subject ?p ?o .
      OPTIONAL {
        ?o ?op ?oo .
      }
    }">
</semantic-sigma-graph>

Persisting graph state

Persistence requires a stable component id. Each graph has its own entry, scoped by query, page and semantic context. Older shared entries are not imported. Restoring a graph preserves its saved positions without restarting a continuous layout.

When persist-graph is enabled, the current graph is saved into browser local storage before the page is unloaded. On reload, the saved graph is restored and a notification is shown with a reset action. 

<semantic-sigma-graph
  id="persistent-network"
  height="600px"
  controls="true"
  persist-graph="true"
  persist-graph-message="The graph has been restored. Use Reset to reload it from the query."
  persist-graph-message-position="tr"
  query="
    CONSTRUCT {
      ?s ?p ?o .
    } WHERE {
      ?s ?p ?o .
    }">
</semantic-sigma-graph>

Events

The Sigma graph component can both emit events and respond to external events. This makes it possible to coordinate the graph with search results, resource views, side panels or other Sigma graphs.

A stable id is strongly recommended whenever events are used. Outgoing Sigma.NodeClicked events include the component id in data.componentId and use the same id as the event source. Incoming events should target the graph id so that only the intended graph instance responds.

Node click payload

{
  componentId: "resource-network",
  id: "<http://example.com/person/alice>",
  node: "<http://example.com/person/alice>",
  nodes: [
    "http://example.com/person/alice"
  ],
  attributes: {
    label: "Alice",
    typeLabels: ["Person"],
    color: "#2980b9"
  }
}

Targeting one graph from another component

The following example targets only the graph whose id is resource-network. 

trigger({
  eventType: FocusNode,
  source: "external-control",
  targets: ["resource-network"],
  data: {
    componentId: "resource-network",
    node: "http://example.com/person/alice"
  }
});

Multiple Sigma graphs on one page

Multiple graphs can be placed on the same page or in separate frames. Use different ids and target events explicitly. 

<semantic-sigma-graph
  id="object-network"
  height="500px"
  query="...">
</semantic-sigma-graph>

<semantic-sigma-graph
  id="event-network"
  height="500px"
  query="...">
</semantic-sigma-graph>

Events emitted by the first graph will use object-network as their component id and source. Events emitted by the second graph will use event-network. This prevents node-click, focus and group-expansion events from crossing between graph instances unintentionally.

Practical notes

  • Use a stable id for any graph that needs to send or receive events.
  • Include rdf:type triples when using type-based colours or grouping.
  • Prefer width="100%" and an explicit height when embedding the graph in a responsive page.
  • Use grouping for high-degree nodes where many targets share the same source, predicate and type.
  • Use node-query for exploratory pages where the user should progressively expand the network.
  • Omit layout on pages with many examples unless a graph needs a different first presentation. The omitted value uses the lightweight circular default.
  • Avoid mounting many live Sigma graphs on a single documentation page. Use one live example and show additional configurations as escaped code blocks or screenshots to avoid exhausting browser WebGL contexts.
  • Enable persist-graph only where restoring user-expanded graph state is useful.
