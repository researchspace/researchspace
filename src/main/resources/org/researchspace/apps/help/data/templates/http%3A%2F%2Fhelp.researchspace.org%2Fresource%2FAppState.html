Application State

The <app-state> component keeps the state of the components inside it (map view, table page, open frames, …) in the page URL or in the backend. A page can then be shared, bookmarked or reopened exactly as the user left it.

Usage

Wrap the components in <app-state> and list, on each component, the state variables to share in shared-state-vars. A component needs an id to share its state.

Components inside <app-state> find it automatically. A component rendered outside of it, for example in an overlay dialog, refers to it with app-state-id="workspace".

Compatible components

Only the components below can share their state. Other variable names in shared-state-vars are ignored with a warning in the browser console.

Component Shared state variables
<rs-dashboard> (Thinking Frames) layoutModel: layout of the frames (positions, sizes, tabs)
openFrames: open frames with their view, resource and label
activeFrameId: selected frame
The three variables are restored together.
<semantic-map> currentExtent: visible area [minX, minY, maxX, maxY] in EPSG:3857
currentZoom: zoom level
<semantic-table> currentPage: current page, starting from 0
filterValue: text in the filter input

The Thinking Frames page uses <app-state> in backend mode: the save button creates a link to the current frames.

Storage modes

Mode How it works Use it for
url (default) The state is encoded in the states URL parameter. With auto-sync="true" the URL follows every change and can be copied from the address bar. Without it, the save button creates a short link (/l/…). Small states, such as a map view or a table page. Very long URLs can be rejected by servers and proxies.
backend The save button stores the state on the server (in the runtime storage, under config/app-states/); the URL only carries stateId. Users are warned before leaving the page with unsaved changes. Large states, such as Thinking Frames layouts.

Configuration

Attributes of the compatible components:

Attribute Description
id Required to share state; the state is stored under this id.
shared-state-vars Comma separated names of the variables to share. Without it the component does not take part.
app-state-id Id of the <app-state> component, needed only when the component is not rendered inside it.

Events

A state can be applied to the components without reloading the page, for example from a button or from another component, with these events targeted at the <app-state> id:

Event Data Description
AppState.ApplyState states: states keyed by component id
mode: merge (default) changes only the given variables; replace also resets the missing ones
transition: {"animate": true, "duration": 1000} animates the change where supported (maps)
updateUrl: whether the URL is updated, defaults to auto-sync 		Applies the states. Components that mount later receive their state when they do.
AppState.LoadState stateId, transition Loads a state saved in the backend and applies it.
AppState.StateChanged states Triggered by <app-state> whenever the shared state changes.

Permissions

Operation Permission
Creating a link with the save button (both modes) services:url-minify
Opening a link to a saved state None: the random state id works as a capability, like short links. Anyone with the link can open it, and the components still apply their own data permissions.
Deleting a saved state (DELETE /rest/app-state/delete/{id}) The user who saved it, or services:app-state:delete:any

Making a component compatible

A component takes part by extending SharedStateComponent (platform/components/semantic/app-state/SharedStateComponent) instead of Component, and adding SharedStateProps to its props. By default:

  • the component registers with the enclosing <app-state> on mount and unregisters on unmount; overrides of componentDidMount and componentWillUnmount must call super;
  • after every setState, the shared variables that changed are sent to <app-state>;
  • a state received from <app-state> is copied into the component state.

Protected methods to override when the state needs more than that:

getSupportedSharedStateVars()Names of the variables the component supports.
handleSharedStateSync(state, {mode, origin, transition})Applies a received state, e.g. moving a map view.
onSharedStateResolved(hasStoredState)Called once, after the stored state (if any) has been applied, or right after mount when the component does not share state. Use it instead of timers to set up defaults.
isAutoSyncEnabled(), updateSharedState(state)Disable the automatic sync and send values that are not in the React state.
getInitialSharedState(), setSharedStateBaseline(state)Keep defaults computed while loading out of the shared state.

Shared values must be plain JSON. Keep them small, especially in URL mode.
